## 1. 术语

| 术语 | 含义 |
|---|---|
| 整场 | 一次完整对战，共 5 轮，先赢 3 轮者胜 |
| 轮 | 双方各 10 滴血，打若干局，直到一方血量 ≤ 0 |
| 局 | 一次发牌 → 轮流行动 → 开牌 → 扣血 |
| 数字牌 | 1～11 各一张，共 11 张，双方共用一副牌组 |
| 王牌 | 特殊牌，见第 4 节 |
| 牌桌 | 每人面前的区域，放着自己的数字牌和「牌桌持续」类王牌 |

## 2. 规则

### 2.1 整场与轮
- 整场开始：双方各从卡池抽 **6 张王牌**（整场只发这一次）。第一局先手随机，之后**每局轮流先手**（跨轮也继续轮流）。
- 每轮开始：双方血量重置为 **10**，手里的王牌**保留到下一轮**。
- 一方血量 ≤ 0 时，本轮结束，对手赢下这一轮。有人赢满 3 轮，整场结束。

### 2.2 一局的流程
1. 洗牌 1～11。双方各发两张：第一张**暗牌**（只有自己能看到），第二张**明牌**。
2. 双方各得 **1 张王牌**。
3. 本局目标点数为 21，双方基础赌注为 1。
4. 从先手开始轮流行动（见 2.3）。
5. 结束条件：**最后一次抽牌或使用王牌之后，双方都各停牌一次**。任何一方抽牌或使用王牌，都会把停牌计数清零。
6. 开牌、判定胜负（见 2.4），输家扣血，扣血量等于输家的赌注。
7. 清空双方牌桌（数字牌和牌桌王牌），开始下一局。

### 2.3 一个回合内能做的事
- 可以使用任意张王牌。限制是：每人牌桌上最多同时摆 **5 张**「牌桌持续」类王牌，「即时」类王牌不受这个限制。王牌只能在自己的回合使用。
- 然后必须二选一，选完回合结束：
  - **停牌**
  - **抽牌**：从牌组顶抽一张明牌。以下情况「抽牌」按钮变灰：已经爆牌、牌组已空、被对手的王牌禁止抽牌。
- 每次通过「抽牌」按钮抽数字牌后，有 **25%** 概率额外获得 1 张王牌。用王牌抽出的数字牌不触发这个概率。
- 王牌**持有上限 20 张**。达到上限时，新获得的王牌直接丢弃并提示。

### 2.4 胜负判定
设目标点数为 T，默认 21，可以被「挑战」类王牌改变。点数 > T 即为爆牌。

| 情况 | 结果 |
|---|---|
| 双方都没爆牌 | 点数更接近 T（更大）的一方赢 |
| 只有一方爆牌 | 没爆牌的一方赢 |
| 双方都爆牌 | 点数**更小**的一方赢 |
| 点数相同 | 平局，双方都不扣血 |

- 王牌用掉就不返还，平局也一样。
- 输家的赌注 = `max(0, 1 + 对手牌桌上「对手赌注 +N」的总和 − 自己牌桌上护盾的总和)`。

### 2.5 王牌的通用规则
- 「撤除」「退回」「交换」这类操作只作用于**明牌**，暗牌不能被操作。目标不存在时王牌**照样消耗**，没有任何效果。
- 「抽 X 牌」时如果 X 不在牌组中，比如在对手的暗牌里或已经在桌上，同样消耗、无效果，并提示「牌组中没有 X，王牌已丢弃」。这也是推理对手暗牌的手段之一。
- 自己爆牌后，所有抽牌类王牌在界面上置灰不能用，因为爆牌后本来就不能抽牌，用了一定无效。
- **最有利的牌**：牌组中能让自己点数 ≤ T 的最大那张；如果没有这样的牌，就取牌组中最小的一张。
- 「牌桌持续」类王牌在本局结束时清空。

## 4. 王牌效果

名称和描述采用游戏官方简体中文，括号里是实现时要遵守的细节。

| 王牌 | 效果 |
|---|---|
| 增加二 | 抽一张王牌。另外，当这张牌在牌桌上时，对手的赌注会增加 2。 |
| 增加二+ | 将对手上一张面朝上的牌退回牌组。当这张牌在牌桌上时，对手的赌注会增加 2。 |
| 护盾 | 当这张牌在牌桌上时，你的赌注会减少 1。 |
| 护盾+ | 当这张牌在牌桌上时，你的赌注会减少 2。 |
| 2～7 牌 | 抽出对应点数的牌。如果它不在牌组中，什么事都不会发生。 |
| 完美抽牌 | 从牌组中抽出最有利的牌。 |
| 终极抽牌 | 从牌组中抽出最有利的牌。另外，抽两张王牌。 |
| 完美抽牌+ | 从牌组中抽出最有利的牌。另外，当这张牌在牌桌上时，对手的赌注会增加 5。 |
| 王牌变换 | 随机放弃两张王牌，然后再抽三张王牌。（手里不足两张时，有几张丢几张） |
| 王牌变换+ | 随机放弃一张王牌，然后再抽四张王牌。 |
| 交换 | 将你和对手抽中的上一张牌互换。（面朝下的牌不能互换；任一方没有明牌就无效） |
| 退回 | 将你上一张抽中的面朝上的牌退回牌组。 |
| 撤除 | 将对手上一张抽中的面朝上的牌退回牌组。 |
| 破坏 | 撤除对手上一张放在牌桌上的王牌。 |
| 破坏+ | 撤除对手放在牌桌上的所有王牌。 |
| 破坏++ | 撤除牌桌上所有对手的王牌。当这张牌在牌桌上时，对手无法使用王牌。 |
| 收割 | 当这张牌在牌桌上时，每次你使用一张王牌，便抽一张新的王牌。（不包括收割本身） |
| 挑战 24 / 27 点 | 当这张牌在牌桌上时，最靠近 24 / 27 点的胜。取代牌桌上（双方）其他已有的「挑战」牌。 |

「上一张面朝上的牌」指该玩家桌上最后一张明牌，包括开局发的那张明牌。退回牌组的牌可以再被抽到。

```
┌─────────────────────────────┐
│ 对手  ❤ 7/10  赌注 3  王牌×5 │
│ [🂠][4][9]        ? + 13     │
│ 对手牌桌王牌: [增加二][护盾]   │  ← 可点开看详情
├─────────────────────────────┤
│ 第2轮 (1:0) · 第3局 · 目标21 │
│ 牌组剩 6 张 · 轮到你          │
│ 「对手使用了 撤除」            │  ← 最近事件
├─────────────────────────────┤
│ 我的牌桌王牌: [挑战24]         │  ← 可点开看详情
│ [7][2][10]        19         │  ← 我的暗牌对我可见（带标记）
│ 我  ❤ 10/10  赌注 1           │
├─────────────────────────────┤
│  [ 王牌 (8) ]  [ 停牌 ]  [ 抽牌 ] │
└─────────────────────────────┘
```

- 三个大按钮：**王牌**（打开弹层，列出手里的王牌，点一张看描述，再点「使用」）、**停牌**、**抽牌**。原作「查看桌上的王牌」改为：牌桌上的王牌直接点击查看详情。
- 不是自己的回合时，按钮全部置灰。
- 开牌时翻开双方暗牌，显示本局结果和扣血，点「下一局」继续（任意一方点击即可）。
- 设置里有「强制重置」按钮，用于状态卡死时重开整场。

## 6. 架构

沿用现有项目的基础设施：Next.js 16、Upstash Redis、Pusher、zustand。不新增环境变量，不改动扑克代码。

```
src/
├── app/
│   ├── twentyone/page.tsx                (入口：?u=aaron|vicky)
│   └── api/twentyone/
│       ├── state/route.ts                (GET：按玩家过滤后的状态)
│       ├── action/route.ts               (POST：所有玩家操作)
│       └── reset/route.ts                (POST：强制重置)
├── lib/twentyone/
│   ├── types.ts
│   ├── cards.ts                          (王牌定义 + 卡池权重)
│   ├── engine.ts                         (纯函数状态机：applyAction(state, action, rng))
│   ├── rng.ts                            (可注入随机数：生产用 Math.random，测试用种子)
│   ├── view.ts                           (服务端状态 → 玩家视角，隐藏对手暗牌/手中王牌/牌组顺序)
│   ├── persistence.ts                    (Redis 读写，key: avic:twentyone)
│   ├── pusher.ts                         (频道/事件名常量)
│   └── store.ts                          (zustand 客户端 store)
└── components/twentyone/                 (Table、PlayerArea、TrumpSheet、TrumpDetail、ActionBar、RoundResult 等)
```

- **服务端权威**：所有规则在 `engine.ts` 里执行，客户端只发送意图（`useTrump`、`stay`、`draw`、`nextHand`）。
- **隐藏信息**：Pusher 频道是公开的，所以推送里只带版本号，客户端收到后再调用 `GET /state` 拿到属于自己视角的数据。对手暗牌、对手手里的王牌（只显示数量）、牌组顺序都不会发给客户端。
- **并发**：每个 action 带上客户端看到的版本号，服务端校验回合归属和版本号，不匹配就拒绝，客户端重新拉取状态。
- **刷新恢复**：状态完整存在 Redis，刷新页面直接拉取恢复。
- **测试**：`engine.ts` 用 vitest 做单元测试，覆盖每张王牌、胜负判定、停牌计数、赌注计算、上限等。
